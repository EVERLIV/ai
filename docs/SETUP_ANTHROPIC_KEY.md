# Подключение ключа Anthropic

Один ключ `ANTHROPIC_API_KEY` обслуживает все ИИ-функции сайта:

| Функция | Что делает |
|---|---|
| `ai-chat` | Чат Анастасии на сайте |
| `ai-property-pick` | ИИ-подбор объектов по критериям клиента |
| `task-ai-report` | Ежедневный дайджест по задачам |

Все три используют модель `claude-haiku-4-5` и берут ключ из переменной
окружения `ANTHROPIC_API_KEY`.

## Главное: где задавать ключ

Функция выполняется **на сервере (VPS)**, а не в браузере. Поэтому:

| Где | Работает? | Почему |
|---|---|---|
| `.env` на VPS (`/opt/supabase/.env`) | **Да — так и нужно** | Отсюда переменные читает контейнер функций |
| Локальный `.env` в проекте | Нет | Его читает только Vite для фронтенда; функция на сервере его не видит |
| `.env.production` | **Нельзя** | Этот файл закоммичен в git — ключ попадёт в репозиторий |
| Переменная с префиксом `VITE_` | **Опасно** | Всё с `VITE_` попадает в JS-бандл и видно любому посетителю сайта |

> ⚠️ Секретный ключ нельзя передавать на фронтенд ни в каком виде. Любой ключ,
> оказавшийся в браузере, можно считать опубликованным.

## Шаг 1. Получите ключ

console.anthropic.com → Settings → API Keys → Create Key. Скопируйте значение
(оно показывается один раз).

Если ключ где-то засветился — в переписке, в скриншоте, в коммите — удалите его
там же в консоли и выпустите новый.

## Шаг 2. Выложите функции на сервер

Ключ бесполезен, если файлов функций нет в контейнере. Признак проблемы в логах:

```
serving the request with /home/deno/functions/ai-chat
worker boot error: could not find an appropriate entry point
```

Это значит, что рантайм жив, но каталога функции на диске нет. Скопируйте функции:

```bash
cd /путь/к/проекту
bash scripts/deploy-functions.sh
```

Проверить, что все функции на месте:

```bash
docker compose exec functions ls -la /home/deno/functions/
```

В списке должны быть `ai-chat`, `ai-property-pick`, `task-ai-report` и `main`.

## Шаг 3. Пропишите ключ на сервере

Подключитесь к VPS и запустите скрипт из репозитория:

```bash
ssh <пользователь>@<сервер>
cd /путь/к/проекту
bash scripts/set-anthropic-key.sh
```

Скрипт запросит ключ со скрытым вводом (он не попадёт в историю команд),
сделает резервную копию `.env`, добавит или обновит `ANTHROPIC_API_KEY`
и ограничит права доступа к файлу.

Если `.env` лежит не в `/opt/supabase/.env`, укажите путь явно:

```bash
SUPABASE_ENV_FILE=/свой/путь/.env bash scripts/set-anthropic-key.sh
```

Вручную то же самое:

```bash
echo 'ANTHROPIC_API_KEY=sk-ant-api03-...' >> /opt/supabase/.env
chmod 600 /opt/supabase/.env
```

## Шаг 4. Перезапустите контейнер функций

Переменная подхватывается только при старте контейнера:

```bash
cd /opt/supabase
docker compose up -d functions
```

## Шаг 5. Проверьте

```bash
curl -s -X POST https://api.arendacity.com/functions/v1/ai-chat \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $SUPABASE_ANON_KEY" \
  -d '{"messages":[{"role":"user","content":"привет"}]}' | head -c 300
```

Ожидаемый ответ — поток строк `data: {...}` с текстом. Если пришёл JSON с полем
`error`, смотрите таблицу ниже.

## Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| `ANTHROPIC_API_KEY is not configured` | Переменной нет в окружении контейнера. Проверьте `.env` и перезапустите: `docker compose up -d functions` |
| `Чат временно недоступен` + в логах `401`/`403` | Ключ неверный или отозван. Выпустите новый в консоли Anthropic |
| `InvalidWorkerCreation: worker boot error: could not find an appropriate entry point` | Каталога функции нет в контейнере — не связано с ключом. Выполните шаг 2 (`bash scripts/deploy-functions.sh`) |
| `Слишком много запросов` | Сработал лимит: 20 запросов в минуту с одного IP |

Посмотреть логи функции:

```bash
cd /opt/supabase && docker compose logs -f functions | tail -50
```

## Стоимость

Используется модель `claude-haiku-4-5` — самая дешёвая текстовая модель
($1 за миллион входных токенов, $5 за миллион исходящих). В контекст каждого
запроса попадает весь каталог аренды (~2,6 тыс. токенов), то есть один ответ
консультанта стоит порядка $0.003–0.005.

Ограничения расхода заданы в самой функции: не более 20 запросов в минуту с IP,
40 сообщений на диалог, 1000 символов на сообщение.
